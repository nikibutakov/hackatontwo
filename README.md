# PCB Defect Inspector

Сервис определения дефектов печатных плат — **задание 4** хакатона «Осенний Хакатон 2026».

> Под дефектами понимаются: разрыв на дорожках платы, непропаянные элементы,
> повреждение компонентов и иные дефекты. Решение — веб-сервис: загрузка фото
> платы с отчётом и вердиктом + **живая камера** с масками дефектов в реальном времени.

## Быстрый старт (2 минуты)

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows (bash: source .venv/Scripts/activate)
pip install -r requirements.txt
uvicorn backend.app.main:app --reload --port 8000
```

- Сайт: **http://localhost:8000**
- Swagger (автодокументация API): **http://localhost:8000/docs**

Сервер стартует в **режиме заглушки** (`USE_MOCK=true`): возвращает фейковые
детекции — фронтенд и вердикты разрабатываются до готовности модели.
Для настоящих моделей: `ml/README.md`, затем `USE_MOCK=false uvicorn ...`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

43 теста, ~2 секунды, ML и веса не нужны (режим заглушки). Покрывают
вердикт, чек-лист ТЗ, сглаживание, декодирование фото (поворот по EXIF)
и весь HTTP API. **Запускайте перед каждым слиянием в `main`** — особенно
в последние часы хакатона, когда правки делаются в спешке.

## Запуск на демо (Windows)

```bat
run_demo.bat          :: реальные модели
run_demo.bat mock     :: заглушка — проверить фронтенд без ML
```

Батник сначала запускает **предполётную проверку** `scripts/check_demo.py`
(Python и зависимости, режим, наличие весов, GPU, метрики-заглушки, примеры
фото, свободный порт) и при ошибках (✗) останавливается. Затем сервер:
без `--reload`, на `0.0.0.0` (доступ через Tailscale / Cloudflare Tunnel),
**ровно один воркер** (модель и сглаживание живут в памяти процесса),
без access-лога.

Замер скорости модели перед демо (цель — от 4–6 FPS на потоке камеры):

```bash
set USE_MOCK=false && python scripts/check_demo.py --bench
```

Чек-лист за час до выступления:
- [ ] `run_demo.bat` проходит без ✗; `--bench` показывает ≥ 4 FPS;
- [ ] в `examples/` лежат 3–5 проверенных снимков (миниатюры на вкладке «Фото»);
- [ ] вторая модель прогрета: один раз переключиться на неё в шапке и обратно;
- [ ] камера открыта по `http://localhost` или HTTPS (иначе браузер её заблокирует);
- [ ] запасной ролик для режима «Видео-файл…» лежит на рабочем столе;
- [ ] в `ml/metrics.json` нет `"placeholder": true` (иначе на вкладке «Метрики» баннер).

## Структура проекта и «кто что дописывает»

| Папка/файл | Роль | Что делать |
|---|---|---|
| `backend/app/model_manager.py`, `ml/` | **ML** | скачать бейзлайн HF, обучить модель на DeepPCB, заполнить `metrics.json` |
| `backend/app/verdict.py`, `smoothing.py`, роутеры | **Backend** | бизнес-правила вердикта, настройка сглаживания, обработка ошибок |
| `frontend/` | **Frontend** | довести UI, режим «видео-файл», вкладка «Метрики», сценарий демо |
| `examples/` | все | 3–5 проверенных фото плат для демо (миниатюры на вкладке «Фото») |
| `run_demo.bat`, `scripts/check_demo.py` | все | запуск на демо и предполётная проверка стенда |
| `docs/` | все | план на сутки, API, архитектура, журнал изменений (CHANGELOG) — читать в первый час |

Каждый файл, требующий доработки, начинается с комментария-шапки
`РОЛЬ: ... / ЧТО ЗДЕСЬ / ЧТО СДЕЛАТЬ (TODO)` — открывайте файл и действуйте по списку.

## Конечные точки (кратко)

Полная документация с примерами: [docs/API.md](docs/API.md) и Swagger `/docs`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/analyze` | полный анализ фото: детекции + сводка + вердикт |
| POST | `/api/frame` | кадр живого потока: сглаженные детекции (облегчённый) |
| GET | `/api/models` | список моделей (какая активна) |
| POST | `/api/models/{id}/activate` | переключить активную модель |
| GET | `/api/metrics` | метрики валидации (из `ml/metrics.json`) |
| GET | `/api/health` | живость API, активная модель, mock-режим |

## Стратегия на жюри (двухмодельная)

1. **Бейзлайн с Hugging Face** (сегментация) — домен реальных фото → живая камера.
2. **Своя модель на DeepPCB** — закрывает разрыв дорожек (open_circuit) из ТЗ
   и даёт метрики улучшения против бейзлайна.

Переключение моделей — прямо в UI (селектор в шапке), на демо показать обе
на одной и той же плате.

## Демо: домашний ПК как сервер

Инференс может идти на домашнем ПК (GPU), а ноутбук на площадке — просто браузер.
Камера в браузере требует HTTPS → `tailscale serve` или Cloudflare Tunnel.
Подробности и запасные сценарии: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
