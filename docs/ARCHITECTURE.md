# Архитектура

## Общая схема

```
┌─────────────────────── Браузер (ноутбук на демо) ───────────────────────┐
│  Вкладка «Фото»        Вкладка «Живая камера»        Вкладка «Метрики»  │
│  upload/drag&drop      getUserMedia → кадры 640px    таблицы mAP        │
│                        цикл «ответил → шлю следующий»                   │
│         canvas: полупрозрачные маски дефектов + подписи                 │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ HTTP JSON (fetch)
┌──────────────────────────────▼──────────────────────────────────────────┐
│                    FastAPI (один сервис, порт 8000)                     │
│  /api/analyze  /api/frame  /api/models  /api/metrics  /api/health      │
│                                                                         │
│  ModelManager ──► MockModel (заглушка, фейковые детекции)               │
│       │        └─► YoloModel: бейзлайн HF (сегментация)                 │
│       │                        своя модель на DeepPCB (детекция)        │
│  VerdictEngine: ok / warning / reject + причина                        │
│  FrameSmoother: подтверждение N кадров + удержание M мс                │
│  StaticFiles: раздаёт frontend/ на "/"                                  │
└─────────────────────────────────────────────────────────────────────────┘
```

## Ключевые решения и почему

### 1. Один сервис вместо микросервисов
FastAPI держит и API, и статику фронтенда. Меньше контейнеров — меньше точек
отказа на демо. Docker-образ остаётся (переносимость), но для GPU-инференса
рекомендован нативный запуск.

### 2. Model Manager — модели взаимозаменяемы
Инференс за одним интерфейсом, активная модель выбирается конфигом/запросом.
Следствия:
- если обучение своей модели не успеет — демо работает на бейзлайне HF;
- на презентации переключение «бейзлайн / наша модель» в один клик —
  это сильный ход: одна и та же плата, две модели, видно улучшение.

### 3. Mock-режим с первого дня
`USE_MOCK=true` — сервер отвечает фейковыми, но правдоподобными детекциями
(с полигонами). Фронтенд и бандлогика вердиктов разворачиваются параллельно
с ML-частью, интеграция потом — это смена одного флага.

### 4. Разделение /api/analyze и /api/frame
Полный отчёт (сводка, вердикт) нужен вкладке «Фото»; потоку камеры нужен
минимальный ответ без лишней работы. Плюс `/api/frame` прогоняет детекции
через FrameSmoother — без него маски на видео «мигают».

### 5. Цикл потока «ответил → шлю следующий»
Никаких WebSocket и очередей: браузер отправляет следующий кадр только после
ответа. Поток сам подстраивается под скорость модели (3 FPS на CPU, 10-15 на
GPU), сервер никогда не оказывается завален кадрами.

## Стратегия моделей (двухмодельная)

| | Бейзлайн HF (keremberke) | Своя (DeepPCB) |
|---|---|---|
| Тип | сегментация (маски) | детекция (рамки) |
| Классы | dry_joint, incorrect_installation, pcb_damage, short_circuit | open_circuit (**разрыв дорожки из ТЗ**), missing_hole, mouse_bite, short, spur, spurious_copper |
| Домен | фото целых плат → **живая камера** | микроскопные вырезки → загрузка фото |
| Слабость | mAP ~0.57, нет open_circuit | нет dry_joint, другой домен света |

Число классов ТЗ закрывается только вместе. Опция-максимум (если время
останется): мёрдж датасетов в одну модель на 10 классов.

## Удалённый сервер и камера (демо-схема)

Инференс — на домашнем ПК (GPU), ноутбук на площадке — браузер.

**Критично:** `getUserMedia` (камера) работает только в secure context —
на `https://…` или `http://localhost`. Прямое открытие `http://<tailscale-ip>:8000`
заблокирует камеру молча (в UI предусмотрено предупреждение).

| Способ | Что даёт | Риск |
|---|---|---|
| **Tailscale + `tailscale serve`** (основной) | приватная сеть + HTTPS на tailnet-домене | WireGuard изредка режут сети площадок |
| **Cloudflare Tunnel** (запасной) | публичный HTTPS-URL через 443 порт | адрес quick-режима временный |
| **Гибрид**: фронт на `localhost` ноутбука, API на Tailscale-IP | камера работает, API удалённо | два процесса на ноутбуке |

Чек-лист по домашнему ПК: отключить сон и автообновление Windows, автозапуск
после пропадания питания в BIOS, `restart: unless-stopped`, репетиция
«выдернул питание → всё поднялось само».

## Цепочка запасных сценариев демо

1. Живая камера → реальный поток (основной).
2. **Режим «видео-файл»** — тот же пайплайн, источник — локальный ролик
   (TODO в `frontend/js/camera.js`). Работает офлайн, честно называется тем же решением.
3. Вкладка «Фото» на заранее отобранных картинках (гарантированный результат).
4. Записанное видео полного демо (последний рубеж).

Скорость решения (см. docs/PLAN.md): если на CPU целевого ноутбука меньше
4 FPS — варианты: s-версия бейзлайна с HF, ONNX-экспорт, перенос инференса
на домашний ПК.

## Каталог файлов

```
backend/app/
├── main.py           # точка входа: FastAPI, роутеры, статика, CORS, /api/health
├── config.py         # ВСЕ настройки: пороги, реестр моделей, правила вердикта
├── schemas.py        # Pydantic-схемы ответов (= форма API)
├── model_manager.py  # Mock/Yolo модели, реестр, переключение
├── verdict.py        # Verdict Engine: ok/warning/reject + русские подписи
├── smoothing.py      # анти-мерцание потока
└── routers/          # analyze.py, live.py, models.py, metrics.py
frontend/             # index.html + css/ + js/ (api, shared, photo, camera, metrics, app)
ml/                   # датасеты, скрипты обучения, метрики (см. ml/README.md)
docs/                 # эта документация
```
