# План на 24 часа (3 человека) + подготовка

## Роли и зоны ответственности

| Роль | Файлы-зоны | Главные задачи |
|---|---|---|
| **ML** | `ml/*`, `backend/app/model_manager.py` | бейзлайн HF → проверка на камере; обучение на DeepPCB; metrics.json |
| **Backend** | `backend/app/*` (кроме model_manager) | вердикт-правила, сглаживание, обработка ошибок, сборка демо-стенда |
| **Frontend** | `frontend/*` | UI вкладок, режим «видео-файл», вкладка «Метрики», презентация |

Каждый файл с доработками начинается с шапки «РОЛЬ / ЧТО ЗДЕСЬ / ЧТО СДЕЛАТЬ (TODO)».

## До хакатона (по 15–30 минут, снимает день рисков)

- [ ] Скачать датасет DeepPCB с Kaggle (нужна авторизация — в день Х может не быть интернета/времени).
- [ ] `python ml/download_hf_model.py --check` — убедиться, что веса открываются текущим ultralytics.
- [ ] Прогнать бейзлайн на фото платы с веб-камеры: сколько FPS на ноутбуке без GPU?
- [ ] Решить схему сервера: локально на ноутбуке или домашний ПК + Tailscale/Cloudflare (`docs/ARCHITECTURE.md`).
- [ ] Распечатать 3–5 плат из датасета (те, на которых модель уверенно находит дефекты).
- [ ] Проверить `git clone` проекта у всех троих и запуск по README (mock-режим).

## Расписание на сутки

### Часы 0–2 · Вертикальный срез (все вместе)
- ML: бейзлайн HF запущен, `USE_MOCK=false`, детекции на распечатке.
- Backend: сервер поднят, `/api/analyze` отвечает реальными детекциями.
- Frontend: вкладка «Фото» показывает маски на реальном ответе.
- ✅ **Контрольная точка: сквозной срез «фото → маски → вердикт» работает.**

### Часы 2–6
- ML: готовит DeepPCB, запускает обучение (идёт в фоне).
- Backend: правила вердикта (количество/площадь), сглаживание.
- Frontend: вкладка «Камера» — поток, отрисовка, FPS-счётчик.

### Часы 6–10
- ML: обучение закончилось → метрики в metrics.json, модель в реестре.
- Backend: переключение моделей, прогрев второй модели.
- Frontend: вкладка «Метрики», селектор моделей в шапке.
- ✅ **Контрольная точка: живая камера со сглаженными масками, обе модели переключаются.**

### Часы 10–16
- Frontend: режим «видео-файл» (офлайн-фолбэк).
- Backend: ошибки, граничные случаи, чистка TODO-заглушек.
- ML: тест на отложенной выборке, при слабых классах — дообучение/тюн порогов.
- Все: замер скорости, решение про CPU/GPU/удалённый сервер.

### Часы 16–20 · Демо-стенд
- Физика: распечатки, тёмный матовый фон, камера на подставке, свет зафиксирован.
- 2 полные репетиции по сценарию (ниже), запись запасного видео.
- docker/запуск проверен на демо-ноутбуке как есть.

### Часы 20–24 · Презентация и буфер
- Слайды: проблема → решение → демо → метрики (бейзлайн vs наша) → план развития.
- Репетиция выступления вслух с таймером.
- Буфер. На хакатонах что-то всегда ломается в последний момент.

## Сценарий демо (3 минуты)

1. **Фото** (30 с): загружаем снимок платы → вердикт «БРАК: разрыв дорожки», таблица детекций.
2. **Камера** (90 с): наводим камеру на распечатку → маски появляются в реальном времени;
   «накрываем» дефект пальцем/картонкой — детекция стабильно держится (сглаживание).
3. **Модели** (30 с): переключаем «бейзлайн → наша модель» на той же плате — видно улучшение.
4. **Метрики** (30 с): mAP бейзлайна против нашей модели, per-class таблица.

## Главные риски

| Риск | Митигация |
|---|---|
| Реальные фото ≠ домен датасета | демо на проверенных распечатках; аугментации при обучении |
| FPS на CPU ниже 4 | s-модель / ONNX / инференс на домашнем ПК через Tailscale |
| Сеть площадки блокирует туннель | Cloudflare Tunnel (443) + мобильный hotspot + режим «видео-файл» |
| Веса HF несовместимы с новым ultralytics | отдельный venv со старым пином (ml/README.md) |
| Авария на домашнем ПК | чек-лист в ARCHITECTURE.md + полное локальное окружение на ноутбуке |

своим кодом · красивый дизайн-система фронтенда · Kubernetes и «масштабируемость».
